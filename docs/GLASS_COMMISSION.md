Recover the complete reachable research corpus into an addressable atlas while recording the observable method used to construct it. The first machine is a concurrent publishing harness. Its listening projection becomes an inspectable structural weight: a versioned behavior graph, grammar, and generator recipe with source-linked witnesses.

## Approach
Use a concurrent event-sourced statechart with declared transitions, an observable tool-action gateway, and a deterministic listening projection. A serial checklist loses concurrent state. A prose-only diary supplies observations but leaves transition enforcement to readers. The selected proposal combines explicit state transitions and durable event records.

## State configuration
A configuration maps region IDs to active state IDs. Initial examples:
corpus=discovering, forms=collecting, behavior=listening, publication=queued.
Region and state vocabularies are extensible through versioned declarations.
Each transition declares region, source, event, destination, guard, effect contract, recovery route, implementation identity, and commission requirement.
Independent regions may react to one event. Event application is atomic across those regions. Execution uses one serialized writer per journal and expected sequence checks.

## Pre-append protocol
Before any governed effect:
1. Persist a declaration or reference its existing version.
2. Persist an intent with input/source IDs, allowed outcome events, bounded budget, required witnesses, and idempotency key.
3. Execute the registered tool adapter using explicit arguments.
4. Persist outcome, actual artifact identities, exit status, and observable decision rationale.
5. Apply matching declared transitions; produce projection and checkpoint.
6. Queue publication and reconcile a receipt with the actual remote main commit.
Abandoned intents remain recoverable and visible. A listener records explicit rationale and tool observations; these are the observable training records.

## Structural weights and generator promotion
A weight is a content-addressed record of states, transitions, typed choices, helper contracts, and supporting execution witnesses.
The minimum listener emits a prefix-tree behavior machine with exact event labels and transitions.
A subsequent engine proposes repeated subsequences as parameterized productions, retaining originals.
Promote a production through input/output contracts, replay fixtures, variation fixtures, resource limits, and named reviewers.
Represent helpers as tiny APIs with implementation digest, typed signature, effects, examples, and recovery behavior.
Every generated action names a registered implementation or an explicit implementation commission.
A trace supplies demonstrated executions; wider behavior receives its own exploration and evidence records.

## Binary and quantum traces
For a spelling trace declare encoding, normalization, width, baseline, byte order, bit order, write policy, and token boundaries.
Spell the word letter by letter; each byte exposes every bit write and every changed bit.
Example profile: UTF-8, zero-filled bytes, MSB first, replace each byte in order.
I: 01001001; N: 01001110. First changed bit for I is bit 6 (counting LSB as zero).
A physical bus write and a stipulated serialized bit-write trace have their own execution-model IDs.
Quantum representation points to an exact PHANTOM/oracle source and identifies address type, basis order, amplitudes/operators/measurements where applicable, codec, and replay witnesses.
Preserve the owner's 'dark matter' term in the Glass vocabulary with its declared phantom-transition definition and provenance.

## Publishing contract
Main is the durable integration target. Each completed work unit triggers publication; a finite debounce coalesces bursts while a running service is active.
Use explicit path allowlists, serialized publication, fast-forward updates, and expected-head checks.
Remote advancement triggers fetch/reconciliation. Preserve local work and publish a conflict checkpoint when human resolution is needed.
Transport failure retains a durable queue and its exact pending work. Resume drains that queue; remote receipt resolves it.
Publication receipts contain repository, branch=main, previous head, published head, included artifact hashes, observation time, and outcome.
Polling/continuous operation requires an installed running service; session execution writes actual receipts as work proceeds.

## Shared continuity and shift addressing
A commission has stable ID, event cursor, source pins, active configuration, outstanding intents, helper registry, and publication cursor.
An agent leases a task and submits version-bound events and artifacts; stale expected versions receive the current cursor for reconciliation.
Suggested addresses: /glass/commissions/{id}/state; /events?after={cursor}; /transitions/{id}; /atlas/entities/{id}/forms/{profile}; /weights/{id}.
GET supplies reads and command descriptions. Authenticated mutations use POST with expected version and idempotency key.

MCP transport, HTTP transport, and downloadable CLI packages share these commands. Initial delivery includes the portable CLI and transport specification; deployment receipts identify active services.
