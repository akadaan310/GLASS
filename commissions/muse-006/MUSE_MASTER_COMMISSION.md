## III. GROWING TOWERS / UNIVERSAL AST FOREST

The tower is not one unbounded in-memory AST. It is a content-addressed, paged **forest of source-linked syntax/semantic graphs** with lazy, bounded adapters. Each transformation records a typed contract, loss report and provenance.

```
SOURCE BYTES (byte span + encoding + digest)
  → TOKEN TAPE (token type + source offsets)
  → CST / AST (parser-specific tree, error nodes, partial parse status)
  → SYMBOL / SCOPE / TYPE GRAPHS (name resolution with evidence)
  → CONTROL-FLOW / DATA-FLOW / SSA (supported languages only)
  → CROSS-LANGUAGE UNISON IR (typed, versioned, source-map preserved)
  → OPERATOR / GRAMMAR CARDS (preconditions, effects, budgets)
  → GENERATOR-OF-GENERATORS (finite, admissible recipes)
  → TESTS / COUNTEREXAMPLES / REPLAY RECEIPTS
  → GLYPH REFERENCES / PREFIX NAVIGATION / VISUAL CONSTELLATIONS
```

Recommended trusted frontends: **Tree-sitter** for incremental parsing where grammar coverage exists; SwiftSyntax and Swift compiler AST/SIL for Swift; TypeScript compiler for TypeScript/JS; CPython `ast` for Python; clang/LLVM for C/C++; Kotlin compiler tooling for Kotlin; javac AST for Java; HTML parse tree and CSS parser for web languages; glTF/scene-graph parsers for 3D assets when supported. Use adapters against fixed versions; no AST should be fabricated from file extension alone. Record parse errors, unsupported operators and incomplete semantic lowering as explicit states.

The graph is a heterogeneous directed multigraph. Nodes are typed and content-addressed. Edges include `CHILD_OF`, `SOURCE_OF`, `ALIAS_OF`, `REFERS_TO`, `GENERATES`, `EXECUTES`, `REWRITES_TO`, `DEPENDS_ON`, `LOWERS_TO`, `SAME_SEMANTICS_UNDER`, `EQUIVALENT_UNDER_PROFILE`, `NON_EQUIVALENT`, `OBSERVED_AT`, `DERIVED_FROM`, `HAS_LICENSE`, `IN_QUOTIENT_CLASS`. Each edge carries a witness, not just visual proximity.

Four independent projections of a language sample must be implementable: lexical occurrence tape, concrete/abstract syntax tree, scope/reference graph, and finite operational trace. Add byte-level bit-write trace as a separate execution profile. Their different "O(1)" transitions require real cost models: direct index lookup may have expected constant time after index construction, but arbitrarily reading/parsing a billion files is not constant time.
